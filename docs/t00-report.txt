T00 — ОТЧЁТ ПЕРВОГО ЭТАПА
Дата: 2026-10-29
Итог: source/contract часть и Kubernetes/toolchain freeze выполнены; локальный live-Sentry
project lifecycle подтверждён для обеих целевых версий. Settings/alerts acceptance и M0
не завершены. T01 scaffold разблокирован только на явно опубликованной alpha surface;

4. Реальные версии

Sentry real calls: официальные self-hosted 24.7.1 и 26.10.1 установлены с нуля и прошли
health-check. В каждой версии local user token выполнил public-API create/read/delete
marker-bearing project без platform и подтвердил active Default key с DSN. 24.7.1 также
подтвердил отсутствие legacy rules при default_rules=false. Обе версии выполнили точный
PUT/GET round-trip трёх inbound filters и пяти typed PII fields. Synthetic events, alert
delivery, detector/action lifecycle, lost-response recovery и SaaS calls ещё не выполнялись.
24.7.1 legacy issue CRUD и 26.10.1 detached workflow CRUD/toggle проверены live.
Kubernetes: постоянный dev smoke работает на v1.35.5; exact v1.35.9/v1.36.5 release
matrix выполнена на локально построенных arm64 kind images. Тот же probe set ранее
прошёл на временном kind v1.36.1, а envtest subset — на control planes 1.35.0 и 1.36.2.
Локально обнаружены kubectl 1.35.3, kind 0.31.0, Docker CLI/daemon 28.3.2, Helm 3.18.0;
создан отдельный Ready context kind-sentry-operator-dev. Это не заменяет release matrix.

5. Fixture/mock only

Все HTTP payloads и HMAC tests являются source-derived fixtures. Они не доказывают
Sentry feature flags, permissions, transport, retries или delivery.

6. Не проверено и почему

- Sentry 24.7.1/26.10.1: project/settings и частичный alert lifecycle выполнены;
  synthetic events, detector/actions, integrations, delivery, lost-response recovery и
  SaaS calls не выполнены;
- Kubernetes matrix: envtest и exact-patch real-cluster probe matrix пройдены;
  project-side prototype registration fence и resourceVersion CAS проверены только в
  envtest, а двухресурсный Connection -> Project protocol и multi-node HA отсутствуют;
- Slack/PagerDuty/Telegram delivery: нет integrations/recipients и внешних credentials;
- generated product CRD/CEL/webhooks: появляются в T01 и требуют повторной matrix;
- conversion webhook deployment, full product RBAC, HA PDB behavior и allow-list egress
  NetworkPolicy не покрыты минимальным dev API-server probe; validating/defaulting
  webhook deployment проверен только как временный probe без certificate rotation, а
  leader election — только single-node failover.

7. Ограничения и риски

- 24.7.1 public alert API не доказал non-destructive disable; presets заблокированы;
- service hook source использует verify_ssl=False; Telegram production route заблокирован;
- usable active key после create подтверждён только на локальных self-hosted стендах;
- marker strategy пока reserved display-name suffix, а не native metadata;
- Kubebuilder 4.16 default dependencies не совпадают с planned controller-runtime 0.24.1;
- exact kind images являются локальными артефактами с записанными image IDs, не
  опубликованными registry images; повторяемость зависит от pinned official release и base;
- T01 разблокирован Kubernetes freeze; M0 и оставшаяся live-Sentry acceptance открыты.
- ADR 0001 разблокирует source-only T01 с уменьшенной честной alpha surface; исходные
  common/advanced alert golden scenarios перенесены в T07, а не отмечены выполненными.
- source-only T01 после этого выполнен отдельно: generated CRD/webhooks прошли envtest и
  exact kind matrix; live evidence меняет только явно перечисленные capability statuses.
