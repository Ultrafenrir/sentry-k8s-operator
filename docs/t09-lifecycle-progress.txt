T09 — LIFECYCLE, SECURITY, HA, AND RECOVERY
Updated: 2026-10-31
Status: Bounded alpha lifecycle implemented with source, envtest, and kind evidence;
production recovery evidence remains deferred

High availability and scheduling

The manager renders two replicas with Lease leader election, readiness/liveness, graceful
shutdown, preferred cross-node anti-affinity, and a PodDisruptionBudget. A three-node kind
probe places replicas on different workers, deletes the leader, and verifies transfer to the
existing follower.

Protected boundaries

Platform credentials, project binding/journal state, routes, hook source plans, mutable
delivery queue, and immutable audit records use separate namespaces and RBAC boundaries.
Public receivers have no ServiceAccount token. Registration writer, hook producer, and
delivery worker receive only the verbs and namespaces required for their role.

Recovery behavior

Manager claims, operation journals, DSN cutover, destination pinning, registration publish,
route revoke/restore, and queue work use idempotency plus compare-and-swap. Periodic work and
retries use bounded jitter. Leader-only janitors process bounded batches with exact revision
deletion. Legacy route migration publishes the new record before deleting the old one and
fails closed on conflicts.

`Retain` removes operator-owned children, journals and verifies removal of the remote
ownership marker, and deletes the protected manager claim and binding without deleting the
Sentry project. `DeleteProject` requires live authorization and ownership evidence.
Deletion work is processed before pause. Protected registration recovery can run before
ordinary Sentry dependencies are ready.

Observability

The controller emits Normal/Warning Kubernetes Events only when a condition status/reason
changes. Messages are fixed and redacted; raw errors and response bodies are excluded.

Product metrics are:

- `sentry_operator_reconciles_total`;
- `sentry_operator_reconcile_duration_seconds`;
- `sentry_operator_condition_transitions_total`.

Labels are bounded controller/outcome/condition/status enums. Namespace, resource name,
Sentry identity, reason text, Secret data, and raw errors cannot enter the metrics API.
Optional ServiceMonitor and PrometheusRule resources use verified TLS and exact
ServiceAccount authorization.

Recovery tooling and audit

`kubectl sentry admin-report` is read-only and prints local names, fixed phases, and
aggregates without protected identities or payloads. `kubectl sentry audit-export` validates
and exports an identity-free immutable mutation trail. Admission denies updates to existing
audit records; a bounded leader-only janitor enforces retention. Delivery-queue retention
also requires a durable audit start before exact deletion and records a closed verified,
recovered, or failed outcome without queue identity or payload data.

Evidence

Envtest covers load, concurrent status transitions, protected-state failure windows, backup
semantic validation, and controller recovery. Kind probes cover leader failover, RBAC,
NetworkPolicy, certificate rotation, authenticated metrics, Prometheus discovery/rules, and
selected upgrades. A protected-state kind drill exported representative records only in
memory, exact-deleted and create-only restored them, verified resumable restore and stable
digest, rejected tampering and live conflicts, and removed all four ownership-labeled drill
namespaces. A clean bounded demo run with the latest local operator image reconciled
the modern and read-only Sentry 26.10.1 projects to Ready, preserved the documented legacy,
unresolved-destination, and paused partial states, and removed all ownership-labeled demo
namespaces during exact cleanup. This is configuration-only evidence and does not prove event
ingestion or notification delivery. Clean configuration-only controller acceptance against Sentry
24.7.1 and 26.10.1 changed live remote regional evidence at a larger revision, observed the
real five-second fencing interval and exact readback, and proved stale and equal-revision
conflicting writers could not change the remote marker. This is not physical multi-cluster
or network-partition failover evidence.

Known local diagnostic limitation

The default cert-manager metrics leaf has a correct service SAN but an empty issuer DN.
macOS curl can reject that certificate while the repository's Prometheus/kind gate succeeds
with CA and hostname verification. Shipped monitoring must not enable insecure TLS as a
workaround.

Remaining work

Long-running production soak, distribution-specific Kubernetes acceptance, persisted
encrypted full-installation backup/restore, hosted upgrade paths, external notification
delivery, and hosted release evidence remain outside the current proof boundary. See
`docs/project-status.md` for the owner-approved backlog.
