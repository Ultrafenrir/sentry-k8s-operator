T05 — TYPED PROJECT CONFIGURATION
Updated: 2026-10-31
Status: Published settings, symbol-source, and issue-ownership surfaces accepted live on both supported versions

Published settings are limited to:

- boolean inbound filters: browser extensions, localhost, web crawlers, and filtered
  health-check transactions;
- legacy-browser filtering as an explicit set of the eight non-deprecated browser-family
  subfilters;
- PII: scrub data, scrub defaults, scrub IP addresses, sensitive fields, and safe fields;
- advanced PII: ordered built-in Relay detectors, bounded redaction methods, exact typed
  event-field selectors, and optional replacement text;
- behavior: auto-resolve hours, default environment selection, native crash-report retention,
  JavaScript/source-map scraping, and allowed browser origins;
- grouping: ordered single-frame enhancement rules and fingerprinting rules over the
  cross-version matcher subset;
- symbolication: an explicit set of the twelve built-in symbol sources shared by both
  supported versions.

Omitted settings remain unmanaged. Present settings are normalized, diffed against the
live project, updated through the narrow public endpoints, and read back. Reconciliation
does not overwrite unrelated project fields and becomes mutation-free after convergence.

Settings mutation requires managed project ownership. A read-only existing-project binding
cannot modify settings. Component conditions separate settings readiness from project/DSN,
destination, and alert readiness so one failure does not erase useful progress.

The Sentry 24.7.1 and 26.10.1 source contracts both expose `filtered-transaction`,
`legacy-browsers`, the same eight non-deprecated browser-family choices, and narrow
`active`/`subfilters` updates. Adapter tests cover the legacy response union, deterministic
set updates, explicit empty-set disablement, and invalid or duplicate input rejection.
Both versions also expose the same read/write fields for `resolveAge`,
`defaultEnvironment`, `storeCrashReports`, `scrapeJavaScript`, and `allowedDomains`. The behavior component
performs its own fresh read, ownership authorization, narrow conditional update, and no-op
convergence. Auto-resolve is bounded to a non-negative 32-bit hour count; crash-report
retention preserves Sentry's `-1` unlimited, `0` disabled, and `1..100` per-issue meanings.
Environment names use Sentry's shared 64-character and no-newline/form-feed/slash contract.
Allowed domains form a non-empty set of DNS hostnames or HTTP(S) origins with an optional
leading wildcard subdomain and fixed port. Paths, query strings, fragments, user information,
duplicate entries, and wildcard ports are rejected; `*` is valid only as the sole entry.

Sanitized fixtures and clean disposable live acceptance cover all five inbound filters,
all five PII fields, and all five behavior fields on Sentry 24.7.1 and 26.10.1. The public
API runs updated and read back every published field. The controller runs introduced
external drift, required one reconcile to repair it, and confirmed a following no-op
reconcile. This is configuration lifecycle evidence only, not event ingestion, filter
behavior, or notification delivery evidence.

Automatic release creation is not published because 26.10.1 exposes it but 24.7.1 does not.
The scraping toggle does not expose or weaken Sentry's outbound TLS verification policy.

Advanced PII never exposes Relay JSON, regular expressions, or selector grammar. The adapter
serializes the typed list into deterministic numeric rule IDs and canonical selectors, validates
exact paths, owns the complete project-level advanced rule set, and treats an explicit empty list
as a clear request. The portable surface contains only the twelve built-in detector types and the
mask, remove, hash, and replace redactions present in both supported Sentry UIs. Offline calls to
the Relay bindings shipped in both pinned images accepted the exact generated JSON and selectors.

Grouping enhancements expose one typed stack matcher and one bounded action per ordered rule.
Fingerprinting exposes one typed event matcher, bounded custom fingerprint values, and an explicit
include-default flag. The adapter emits quoted canonical rule text and owns each complete ordered
list independently; explicit empty lists clear it. The native enhancement bindings in both pinned
images accepted the exact generated text, and both source grammars accept the generated
fingerprinting subset. Raw rule text, caller/callee grammar, categories, range actions, regex PII,
and arbitrary vendor settings remain outside v1alpha1.

Grouping profile selection and secondary-grouping migration remain outside v1alpha1. Sentry
24.7.1 accepts those project fields, but Sentry 26.10.1 explicitly rejects manual updates to
`groupingConfig`, `secondaryGroupingConfig`, and `secondaryGroupingExpiry` and no portable public
mutation contract exists. This incompatibility is a documented version boundary, not a capability
inferred from a version string.

Symbolication settings expose only the portable built-in source set: `amd`, `autodesk`,
`chromium`, `citrix`, `electron`, `intel`, `microsoft`, `mozilla`, `nuget`, `nvidia`,
`ubuntu`, and `unity`. The field has set semantics, is serialized in a fixed order, and an
explicit empty set disables every managed built-in source. Sentry 26.10.1 additionally
exposes `proton`, but it is absent from 24.7.1 and therefore is not part of the common
contract. Native source-server mapping also remains outside the common contract because
26.10.1 exposes `enableNativeSourceServerMapping` while 24.7.1 does not. Custom symbol
sources are separate secret-bearing children and are not represented by this settings field.

The custom child contract supports the portable HTTP, S3, and GCS types. Layout and casing
are bounded enums. HTTP requires HTTPS; S3 requires a portable region; and all credentials
come from keys in Secrets in the SentryProject namespace. Azure remains unavailable because
24.7.1 does not expose it. The controller validates every desired child before its first
mutation, generates a deterministic external identity and ownership-bearing name, and stores
only that safe metadata plus a SHA-256 desired-state digest in protected state. Credentials,
access keys, private keys, request payloads, and remote redaction placeholders never enter
public status or protected bindings.

Creation recovers a lost response by finding the deterministic identity and requiring a
successful full update before committing the protected digest. A successful update is
required for credential rotation because a redacted GET cannot prove the new credential.
Visible drift is repaired independently, convergence is mutation-free, and explicit empty
desired state deletes only exact pinned identities. `SymbolSourcesReady` reports this
component separately; read-only existing projects and Standby connections cannot declare it.

Issue ownership is a separate independently reconciled component. The public contract
supports an ordered list of bounded `path`, `module`, `url`, and `tag` matchers; readable
team owners; explicit `AllMembers` or `NoOne` fallthrough; issue-owner, suspect-commit, or
disabled auto-assignment; and CODEOWNERS synchronization for data already imported into
Sentry. Every referenced team must be the project's primary team or a declared additional
team grant, and it must remain authorized by the connection policy. Direct user/email
owners and raw ownership grammar are not part of the alpha API. Repository linkage is a
separate `codeMappings` component that references only connection-owned integration and
repository aliases; all numeric external identities remain protected.

The issue-ownership engine validates and renders canonical Sentry rules before its first
read, performs a fresh public ownership read, revalidates the regional ownership fence
immediately before a conditional update, reads the result back exactly, and becomes
mutation-free after convergence. Admission rejects issue ownership for read-only existing
projects and Standby connections. `IssueOwnershipReady` reports this component separately,
and a project-access failure blocks ownership reconciliation so a referenced team is never
written before its project grant succeeds.

Clean configuration-only runs on Sentry 24.7.1 `feature-complete` and Sentry 26.10.1
`errors-only` updated and read back the public ownership endpoint. The controller runs then
introduced ownership drift, required exactly one ownership PUT to repair it, and confirmed
a following no-op reconcile with `IssueOwnershipReady=True`. This is configuration
reconciliation evidence only; it does not prove issue assignment from an ingested event or
CODEOWNERS import behavior.

Repository code mappings now have matching 24.7.1 and 26.10.1 source contracts, typed HTTP
adapters, protected identity bindings, durable lost-create recovery, exact catalog
resolution, optional CODEOWNERS fetch/import/update/delete, admission coverage, and controller
envtest coverage. Clean configuration-only direct API runs on both supported versions proved
catalog resolution, mapping create/update/read-back/delete, and Sentry CODEOWNERS child
create/read-back/delete. Full-controller runs proved alias resolution, create, visible-drift
repair, mutation-free convergence, safe public status, protected identities, and exact
cleanup. The disposable integration deliberately has no valid external provider credentials,
so fetching a real repository CODEOWNERS file remains unverified external evidence. These
runs do not prove event ingestion, issue assignment, or notification delivery.

Verification: `make verify-t05` plus the configuration portion of
`make sentry-live-config-api` on the disposable target. Clean configuration-only public API and
full-controller runs on both supported versions updated and read back advanced PII, grouping
enhancements, fingerprinting rules, and built-in symbol sources. The same clean runs created
HTTP, S3, and GCS custom sources, verified credential redaction, rotated the HTTP credential,
repaired deliberate visible drift with exactly one controller mutation, confirmed a following
mutation-free reconcile, and removed all exact owned sources. Event ingestion, symbol
download, native symbolication, and notification delivery were intentionally not run.
