T02 — SENTRY CLIENT, CONNECTION, AND NAME RESOLVERS
Date: 2026-10-29
Status: Complete for source/contract scope; live behavior recorded separately

The HTTP client validates the base URL, uses bounded timeouts and response bodies, supports
verified HTTPS by default, permits explicit self-signed TLS bypass, and permits plain HTTP
only with `allowInsecureHTTP: true`. It never logs tokens or raw response bodies.

`SentryConnection` loads all referenced Secrets from the fixed operator namespace and
rebuilds the in-memory client when a referenced Secret rotates. It publishes a redacted
`CredentialsReady` condition. HTTP allowance and TLS verification bypass remain distinct.

Access policy authorizes namespace, team, existing-project observation/DSN use, managed
creation, and destination selectors. Exact name resolvers return not found or ambiguous and
never expose the selected private ID in public status.

The connection controller does not infer capabilities from a server version. Capability
evidence must be supplied by an acceptance process or future discovery workflow. This is a
deliberate fail-closed boundary.

Uncertain external mutation is not resolved by the generic client. T03 journals mutations
in Kubernetes and recovers them through exact markers and read-after-write verification.

Verification

`make verify-t02` covers URL/transport validation, redaction, pagination, policy, resolvers,
Secret rotation, and uncertain-response behavior using bounded fixtures and envtest.
