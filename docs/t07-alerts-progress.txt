SENTRY CONFIGURATION OPERATOR — T07 ALERTS PROGRESS
Date: 2026-10-30
Status: In Progress; typed public API, protected controller lifecycle and concrete legacy
and modern adapters Verified locally; live external notification delivery remains gated.

Implemented lifecycle core and its current evidence boundary:

- `internal/alerts` defines a narrow adapter-neutral desired model for first-seen,
  regression and event-count rules. It accepts only readable local destination keys; raw
  queries, native model names, adapter families and external IDs are not inputs.
- Adapter capability selection is deterministic and then pinned in protected state. A
  controller upgrade cannot silently switch an existing alert to a different family.
- Every external child has an exact protected `AlertBinding`: adapter, external identity,
  canonical desired hash, enable state, destination keys and the full ownership marker.
- Protected binding decode is fail-closed: local key, pinned adapter, SHA-256 hash, exact
  project marker, external identity and unique destination keys are validated before state
  can reach reconciliation. Alert bindings are forbidden on External/ReadOnly records.
- Reconcile observes the exact bound identity and marker before update, toggle or delete,
  and calls the supplied authorization function immediately before every mutation.
- Create uses an adapter `Ensure` contract keyed by project, local key and marker. A concrete
  adapter must recover a lost create response by that marker instead of issuing a blind
  second POST.
- Every ensure/update/toggle/delete uses the existing protected `OperationJournal` contract.
  The runner persists Planned -> Submitted before the external call, verifies a resumed
  Submitted operation before retry, retries only the same idempotency hash, and persists
  Verified only after observing the requested result. A different desired hash cannot
  replace uncertain Submitted intent.
- Every journaled alert mutation also emits a closed-schema audit event before an external
  apply and after its verified/recovered/failure outcome. Events contain only timestamp,
  fixed component/action/outcome/reason enums, local project/rule and journal revision;
  external identity, desired hash, payload and raw error are not representable. If the audit
  sink is unavailable before Apply, the adapter is not called and Submitted intent remains
  recoverable. A verified result is recorded before the journal advances to Verified.
- The Kubernetes-backed journal now validates its own transition graph: records start at
  Planned; kind/local resource are immutable; Submitted can advance only to Verified/Failed
  with the same hash; only terminal operations may start a new Planned intent. Unknown
  phases, malformed hashes and stale revisions fail closed.
- An absent alerts block performs no management. An explicitly managed empty map deletes
  all and only protected operator-owned alert children and records per-key tombstones.
- Removed alert keys are processed before new/update work, establishing the first half of
  same-generation alert-before-destination cleanup ordering. The result releases a requested
  destination cleanup only when no desired rule and no surviving protected binding refers
  to it; absent alert management or a failed alert deletion keeps cleanup blocked.
- Update support is capability-gated. When safe in-place update is unavailable the core
  returns `AlertUpdateUnsupported`; it does not silently recreate, introduce downtime or
  risk double notifications.
- Canonical hashes sort destination references and exclude enable state, so a toggle does
  not trigger an unrelated rule update. Invalid/unsupported rules fail per alert and do not
  block independent valid rules.
- `ModernHTTPAdapter` implements the pinned Sentry 26 `metric_issue` pair as one protected
  composite detector/workflow identity. Names carry project slug, local key, canonical
  desired hash and the exact parent ownership marker; both children and their bidirectional
  link are checked before update, toggle or delete. Delete now receives the expected marker
  through the common Adapter contract, closing the last point at which a concrete adapter
  otherwise could not compare protected ownership immediately before mutation.
- Modern event-count rendering is deliberately narrow: events/count(), error event type,
  static high/OK conditions and one workflow action filter. Slack and PagerDuty actions are
  built only from active protected destination identities; readable local keys remain the
  desired input. Telegram, missing, revoked and malformed identities fail closed before an
  HTTP mutation. The adapter never accepts raw native action/config/query payloads.
- Ensure lists every paginated organization workflow and project metric detector, matches
  the complete managed name, rejects duplicates/half-pairs, and reuses a detached workflow
  created before a lost response. A lost detector POST response is recovered from the same
  workflow/detector pair with no second POST. Update is workflow-first and treats the
  detector hash/state as authoritative, so an interrupted pair update/toggle can safely
  converge without changing either identity.
- `LegacyHTTPAdapter` implements both pinned Sentry 24.7.1 families without pretending that
  scheduled deletion is a pause operation. The issue adapter renders only first-seen and
  regression conditions; the metric adapter renders only events/count() above-threshold
  rules. Both use the same canonical managed name, exact protected Slack/PagerDuty
  identities, paginated name recovery, stable numeric IDs and ownership checks immediately
  before DELETE. A repeated Ensure after an uncertain create response finds the exact
  marker/hash-bearing child instead of issuing a second POST.
- Legacy create and update require `enabled=true`. Issue enable is implemented for recovery
  of an already-disabled bound rule, but disabling issue rules and either metric toggle
  return `ErrLegacyToggleUnsupported`. Legacy capabilities therefore must not advertise
  `SupportsToggle`; no controller may translate disable into DELETE or silently recreate a
  rule. This keeps the adapter useful for contract testing and future explicitly constrained
  profiles without weakening the common lifecycle contract.

Verification:

- `make verify-t07-core` runs the alert and binding packages under the race detector and
  vet, checks lifecycle guards, the typed generated CRD and explicit compatibility profiles.
- Fake-adapter tests cover create/update/toggle/delete, deterministic pinning, repeated
  authorization, ownership loss, missing/unsupported adapter, no-recreate update failure,
  per-alert isolation, tombstones, delete-before-create ordering, canonical hashes, and
  preservation of an unbound manual alert. Failure injection also covers a child created
  before a lost Ensure response: restart recovery returns the same child, not a duplicate.
  A policy failure during alert deletion is verified to block destination cleanup release.
- TLS-backed HTTP adapter tests cover the complete modern metric pair lifecycle, exact
  source-derived Slack/PagerDuty payloads, composite identity stability, idempotent Ensure,
  a connection drop after detector creation, ownership denial before DELETE, unsupported
  Telegram rejection and strict identity decoding.
- TLS-backed legacy adapter tests cover first-seen/regression and event-count payloads,
  exact Slack/PagerDuty action identities, idempotent Ensure, update with stable ID,
  marker denial before DELETE, issue delete-to-disabled, metric delete-to-404 and a dropped
  connection after an issue-rule POST followed by recovery without another POST.
- Audit failure injection proves that no adapter call occurs when the start event cannot be
  recorded, and that the protected journal remains Submitted. A separately verified resumed
  operation records `Recovered` and closes without authorization or a second Apply. Sentinel
  JSON checks reject external identity, desired hash and raw adapter error leakage.
- The existing real-envtest protected-state round trip now includes an alert binding and
  alert adapter pin; backup, deletion, restore, idempotent re-restore and digest-stable
  re-export preserve the record exactly.
- The read-only admin report exposes only aggregate total/enabled/disabled/tombstone counts.
  Sentinel external identity, trigger and tombstone key tests confirm that protected alert
  values are absent from its JSON.
- A temporary protected binding in the persistent Kubernetes 1.35.5 kind cluster exercised
  the built `kubectl-sentry admin-report` binary. It reported exactly 1/1/0/1
  total/enabled/disabled/tombstone counts, emitted none of the sentinel identity/trigger/key,
  and the probe Secret was removed while the controller remained 2/2 Ready.

Evidence boundary and remaining work:

- Live 24.7.1 verified marker-bearing legacy issue rule create/read/update/delete-to-inactive
  and exclusion from the active list. It also confirmed that delete is scheduled deletion,
  not a non-destructive disable toggle.
- Live 24.7.1 also verified an events count() legacy metric alert with empty actions:
  create/read/update by stable ID and delete-to-404. Its public API still has no accepted
  non-destructive disable/enable route.
- Live 26.10.1 verified workflow create/read/update and bulk disable/enable by exact ID.
  It then created an attached `metric_issue` detector with an events/count() data source,
  static high/OK thresholds and no external actions; detector read, bulk disable/enable and
  delete-to-404 all preserved exact identity. Workflow delete-to-404 completed afterwards.
  This proves a usable local detector/workflow lifecycle, but not actions or delivery.
- `spec.alerts` now publishes only first-seen, regression and event-count with local
  Slack/PagerDuty destination references. An absent field remains unmanaged; an explicit
  empty map deletes protected children. Status exposes only local key/state/reason and an
  `AlertsReady` condition. Adapter, remote identity, desired hash and marker stay protected.
- `SentryConnection.spec.compatibility.alerts` is an explicit platform-owned assertion:
  `legacy-24.7.1` selects the combined issue/metric adapter and `modern-26.10.1` selects the
  verified metric_issue detector/workflow adapter. Missing or incompatible profiles fail
  before mutation. Legacy accepts only enabled desired rules because delete is not a pause;
  modern supports toggles. A trigger-family change that lacks safe in-place semantics also
  fails without delete/recreate.
- The project controller now resolves destinations first, reconciles alerts through the
  protected operation journal and audit sink, reauthorizes every mutation against current
  project policy/profile/bindings, CAS-persists alert bindings/pin/tombstones, and publishes
  redacted per-rule status. Destination removal is first persisted as CleanupPending and
  passed to the alert engine; only its ReleasableDestinations proof can remove the protected
  destination identity or revoke a Telegram route. Envtest covers create, safe status,
  protected identity/pin, same-generation alert+destination removal, a failed Sentry delete
  which preserves both bindings, successful retry, and tombstone persistence.
- Live Slack/PagerDuty delivery acceptance and additional portable trigger mappings remain
  outside the verified boundary; they do not block the implemented configuration lifecycle.
- The closed audit core now covers managed project create/delete, internal alert mutations,
  Telegram registration, destination cleanup and external Telegram delivery through the
  durable immutable export/retention backend. Queue-administration coverage remains required
  for a complete operator audit trail.
