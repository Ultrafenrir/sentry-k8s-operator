ADR 0001 — SOURCE-ONLY ALPHA SURFACE
Date: 2026-10-29
Status: Accepted for T01

Context

The initial plan described fields that could not be proven consistently across Sentry
24.7.1, Sentry 26.10.1, and SaaS without live credentials. Publishing those fields in a
v1alpha1 CRD would create a compatibility promise before an adapter contract existed.

Decision

T01 publishes only source-confirmed, adapter-neutral fields:

- SentryConnection identity, credential references, transport policy, organization, access
  policy, compatibility selection, and readable integration defaults;
- SentryProject create-or-use identity, owner, pause, lifecycle, DSN output, typed filters,
  typed PII settings, readable destinations, and the bounded common alert catalog;
- status conditions and component summaries that exclude private external identities.

Raw Sentry filter, grouping, PII, alert, or workflow JSON is not part of the public alpha
API. Unsupported vendor-specific fields must be added only after an ADR and evidence across
the supported targets.

Required golden cases

1. Minimal managed creation with a readable team.
2. Existing-project observation without DSN consumption.
3. Existing-project observation with authorized DSN consumption.
4. Managed project with the complete published filter and PII contract.
5. Managed project with adapter-neutral Slack, PagerDuty, and Telegram selectors.

Consequences

The public surface stays smaller than the full Sentry API. Capability discovery and explicit
compatibility profiles fail closed instead of guessing from a version string. Later API
growth requires the evolution rules in ADR 0002.
