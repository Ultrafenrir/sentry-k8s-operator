2. Ресурсы

SentryConnection — cluster-scoped platform-owned CR:
- HTTPS URL и organization;
- tokenSecretRef и optional caBundleSecretRef без namespace: Secret всегда читается из
  фиксированного namespace оператора;
- default connection flag;
- access rules owner -> exact namespace names, teams, allowCreate, observe/consumeDSN;
- destination grants Slack/PagerDuty/Telegram только по читаемым именам;
- integration defaults и Telegram platform Secret refs/receiverURL;
- status conditions, serverVersion, capabilities и несекретный registrationCommit fence.

SentryProject — namespaced service-owner CR:
- ровно один project.create или project.use;
- optional connection, DSN customization, source-confirmed settings, destinations;
- paused=false и lifecycle.onDelete=Retain defaults;
- project.use запрещает settings, destinations и DeleteProject;
- destination содержит ровно один из slack/pagerDuty/telegram;
- spec.connection и spec.project immutable;
- owner, manager, внешние IDs, alerts, profile, grouping и advanced отсутствуют в spec;
- status показывает только безопасные origin/accessMode/projectURL/DSN Secret, readable
  DSN client-key name, destination summaries и conditions. External key identity и DSN
  value остаются protected/Secret-only.

Output Secret contract:
- default name: <metadata.name>-sentry;
- единственный стабильный platform key: SENTRY_DSN;
- public DSN value никогда не попадает в CR status.

3. Limits и semantics

- destinations max 20;
- access rules max 100, unique by owner;
- namespace/project/team/key lists bounded;
- false и omitted различаются pointer boolean fields;
- [] и omitted различаются pointer slice PII fields;
- destination names — lowercase DNS labels;
- Secret references состоят ровно из name + key;
- consumeDSN обязан быть subset observe;
- allowCreate требует хотя бы одну разрешённую team.

4. Admission и conversion

Generated mutating/validating webhooks имеют failurePolicy=Fail и sideEffects=None.
Schema/CEL повторяет критические правила, webhook повторяет safety checks и добавляет:
- HTTPS/Secret/name validation;
- policy registration fence;
- immutable identity;
- DSN name default при явно заданном пустом dsn block.

Conversion: strategy=None, см. ADR 0002.

5. Golden contract

Ровно шесть positive fixtures находятся в testdata/t01/golden/:
1) minimal Managed create;
2) External observe без DSN request;
3) External consume DSN с пустым dsn block и default Secret;
4) полный опубликованный filters/PII settings contract;
5) Slack/PagerDuty/Telegram selectors;
6) typed first-seen и event-count alerts с локальными Slack/PagerDuty references.

Schema/CEL negative fixtures находятся в testdata/t01/negative/. Event-count без threshold
отклоняется schema/CEL, а dangling и Telegram notify references — admission webhook.

7. Передано следующим задачам

- controllers пока scaffold-only и не обращаются к Sentry;
- policy evaluator/resolvers принадлежат T02;
- Secret watch, DSN publisher и binding принадлежат T02–T04;
- destination runtime capability остаётся Unknown до T06;
- alerts surface и controller lifecycle приняты в T07 после version-pinned evidence;
- certificate rotation/recovery остаётся T09; T01 проверил static TLS deployment и
  fail-closed outage, не заявляя rotation готовой;
- duplicate readable external names уже имеют T00 executable negative tests, а runtime
  policy/name integration выполняется в T02;
- forbidden destination grant проверяется будущим T02 policy evaluator до любого
  resolver/API call; schema уже не допускает обход grant внешним ID.
