SENTRY KUBERNETES OPERATOR — KUBERNETES COMPATIBILITY
Reviewed: 2026-10-31
Status: Kubernetes 1.35/1.36 source, envtest, and kind baseline established for alpha.

1. Toolchain freeze

- Go toolchain: repository-pinned Go 1.26.x.
- controller-runtime and Kubernetes libraries: pinned by `go.mod` and `go.sum`.
- CI envtest: Kubernetes 1.35.0 lower-bound assets in one test job.
- Local compatibility matrix: Kubernetes 1.35.0 and 1.36.2 through `make test-matrix`.
- kind default e2e node: pinned Kubernetes 1.35.5 image and digest.
- cert-manager: v1.21.1 in the current real-cluster probes.
- Prometheus Operator: v0.94.2 in monitoring acceptance.

Version changes require dependency review, regenerated CRDs/deepcopy/RBAC/chart artifacts,
admission tests, the local envtest matrix, and the relevant kind gates.

2. API contract

The alpha API uses structural OpenAPI schemas, CEL validation, status subresources, printer
columns, and admission webhooks. It serves and stores one version. Required negative tests
cover create-or-use exclusivity, field limits, transport combinations, policy selectors,
alert compatibility, destination shapes, lifecycle choices, and immutable protected-state
rules.

4. Local development findings

Use `.tools/bin/kind`, not an arbitrary system kind. A previously installed system kind
v0.31.0 could create the cluster but failed to load the local image, while the pinned
repository binary completed the standard load path.

The persistent development context is `kind-sentry-operator-dev`. Disposable matrix and
failure-injection scripts must refuse to reuse an existing cluster name and delete only the
cluster they created. After a disposable probe, restore or explicitly report the active
context.

5. Runtime deployment evidence

The default manager has two replicas, leader election, health probes, graceful shutdown,
preferred anti-affinity, PodDisruptionBudget, restricted pod security settings, admission
webhooks, cert-manager certificates, and authenticated TLS metrics. Dedicated kind probes
cover leader loss, certificate rotation, NetworkPolicy, least-privilege metrics access,
Prometheus rule loading, and selected failure windows.

6. Commands

```sh
make verify-t01-generated
make verify-samples
make test-matrix
make test-e2e
```

Run the narrower `verify-tNN-*` targets first while iterating. `make test-e2e` creates and
deletes its explicitly named kind cluster unless configured otherwise.

7. Evidence boundary

Envtest proves Kubernetes API/controller behavior, not container networking or Sentry.
kind proves the selected local dataplane and images, not a managed Kubernetes distribution.
Production distribution acceptance, long-running upgrade soak, and hosted release evidence
remain separate work.
