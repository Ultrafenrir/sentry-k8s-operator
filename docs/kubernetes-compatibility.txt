5.1. T00 API-server probes на dev v1.35.5

Команда: make verify-kubernetes-probes
Fixtures: testdata/kubernetes/t00-probes/
Probe API group: t00.sentry-operator.dev (не является выбранным product API group).

Подтверждено реальным API server v1.35.5:
- structural apiextensions.k8s.io/v1 CRD устанавливается и получает Established;
- defaulting выставляет spec.paused=false и lifecycle.onDelete=Retain;
- CEL требует ровно один project.create/project.use, включая negative neither/both;
- CEL запрещает settings/destinations/alerts вместе с project.use;
- CEL запрещает lifecycle.onDelete=DeleteProject вместе с project.use;
- status subresource обновляет status без изменения generation/spec;
- probe Role разрешает get/list/watch CR и update/patch только status subresource;
- тот же ServiceAccount не может update/delete main resource и читать Secrets;
- policy/v1 PDB minAvailable=1 реально блокирует Eviction единственного Ready pod;
- после удаления probe PDB тот же Eviction проходит;
- networking.k8s.io/v1 default-deny реально блокирует новую HTTP связь между probe pods;
- два client-go LeaseLock кандидата проходят leader failover после ReleaseOnCancel;
- Lease holder после failover совпадает со вторым кандидатом;
- conversion.strategy=None сохраняется сервером.

Первая версия probe была реально отклонена API server: properties нельзя сочетать с
additionalProperties:false в тех же structural schema nodes. Исправленная версия полагается
на стандартное CRD pruning неизвестных полей. Это ограничение нужно сохранить при T01
generation/review, а не переносить JSON Schema механически.

Скрипт использует отдельный namespace sentry-operator-t00-probe и удаляет namespace и
probe CRD после выполнения. Он не устанавливает product CRD; RBAC result доказывает только
subresource separation для probe Role, а не полный product permission set. PDB result
доказывает Eviction behavior на single-node v1.35.5, но не HA failover. NetworkPolicy
enforcement проверен только для default-deny на kindnet; allow-list/DNS/egress policy ещё
не спроектированы. Conversion webhook deployment не проверен.

Отдельный make verify-kind-admission собирает минимальный linux probe из
tools/t00-admission-probe/, загружает его напрямую в kind и временно устанавливает
admissionregistration.k8s.io/v1 MutatingWebhookConfiguration и
ValidatingWebhookConfiguration с failurePolicy=Fail, TLS Service и CA bundle. На v1.35.5
и v1.36.1 API server подтвердил default dsn.secret=<metadata.name>-sentry и отклонил
изменение immutable spec.project. После scale-to-zero новый объект fail-closed отклоняется
API server, то есть failurePolicy=Fail проверена поведением, а не только manifest. Namespace,
webhook registrations и probe CRD удаляются после каждого запуска. Это проверяет
deployment/registration path, но не certificate rotation, recovery после outage или
product webhook code.

Leader probe запускается отдельно командой make verify-leader-election, использует
namespace sentry-operator-leader-probe и удаляет его после проверки. Это подтверждает
Lease acquisition/release/failover на одном API server, но не replica crash, network
partition, multi-node scheduling или controller state recovery.

Connectivity image source:
busybox@sha256:d82c2ab94640ded77cf76514ce6a84870761105058a4a9e51b05a8a79be97a6c
(BusyBox 1.37.0 linux/arm64 manifest). Локальный tag busybox:t00-arm64 загружается pinned
kind v0.32.0; workload использует imagePullPolicy=Never. Подготовка:

7. Решение

Kubernetes/toolchain freeze принят для начала T01 scaffold:
- exact-patch v1.35.9/v1.36.5 probe matrix выполнена;
- toolchain, envtest assets, node-image builder/base и проверенные local image IDs
  закреплены;
- failure evidence admission readiness сохранено как установка ordering requirement;
- Unknown строки не объявляются поддержкой и переносятся в соответствующие product tasks.

Product generated dependency set и generated CRD появятся только при T01 scaffold.
T01 закрепил итоговые go.mod/go.sum и generated artifacts. Двухресурсный policy fence
проверен на real status subresources envtest 1.35/1.36; его real-cluster HA/expiry recovery,
certificate rotation, multi-node HA и conversion webhook остаются Unknown.
conversion.strategy=None является выбранной alpha стратегией и проверена. Source
availability сама по себе не считается proof.

Текущий default manifest рендерит controller Deployment с двумя replicas,
`--leader-elect`, preferred pod anti-affinity и policy/v1 PDB minAvailable=1. Это
структурная готовность к HA и не заменяет multi-node/failure acceptance; соответствующая
строка остаётся Unknown за пределами уже выполненного Lease failover probe.

Дополнительный development probe 2026-10-30 (не часть exact-patch support matrix):
persistent single-node kind v1.35.5 с cert-manager v1.21.1 поднял новый default manifest
2/2, certificates Ready, PDB allowedDisruptions=1 и обе ingress NetworkPolicy. Удаление
точно определённого Lease leader pod передало holderIdentity второй реплике, а Deployment
вернулся к 2/2. Single-node probe не доказывает node failure или topology availability.
