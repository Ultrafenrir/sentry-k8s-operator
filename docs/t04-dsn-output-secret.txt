T04 — DSN И OUTPUT SECRET
Дата: 2026-10-29
Статус: Complete для source-derived/mock/Kubernetes scope. Live Sentry остаётся Unknown.

1. Client keys

internal/dsn читает только GET всех страниц
/api/0/projects/{organization}/{project}/keys/. POST/PUT/DELETE client keys отсутствуют.
Source-derived fixtures Sentry 24.7.1 и 26.10.1 подтверждают используемые поля: readable
name/label, isActive и dsn.public.

Выбор выполняется только после успешных project identity и policy checks:

- один active key выбирается автоматически;
- несколько active keys требуют точного уникального dsn.clientKey по readable name/label;
- внешний ID никогда не принимается как пользовательский selector;
- выбранный ID и hash selector сохраняются только в protected binding;
- неизменный selector не переключается после external rename или same-name replacement;
- status публикует только bounded readable `dsnClientKey`; внешний ID и DSN отсутствуют;
- rename pinned key сохраняет исходный readable baseline в protected binding и стабильно
  показывает `DSNReady=True/ExternalNameChanged` на каждом успешном reconcile. Это warning,
  а не outage: identity и Secret остаются current. Явное изменение selector создаёт новый
  verified baseline;
- полный успешный список без pinned active key доказывает revoke; 403, timeout и transport
  error не доказывают revoke и сохраняют рабочий Secret.

Public DSN принимается только как HTTPS URL с public key в username и без password.
Значение не записывается в binding, status, condition или error.

2. Authorization

Managed create публикует DSN только после exact manager claim, binding identity, marker и
текущего Manage policy. project.use до чтения keys требует одновременно observe и
ConsumeDSN по тому же slug. ReadOnly reader не получает owner/claim и не вызывает Sentry
mutation.

Непосредственно перед каждым create/update/delete Secret callback повторно читает:

- exact SentryProject UID, generation, deletion и paused state;
- текущий SentryConnection policy;
- protected binding identity/access;
- для manager — exact claim без handoff;
- для reader — ReadOnly + ConsumeDSN.

Изменение authorization между plan и write возвращает ErrAuthorization. Competing writer
останавливается в T03 до client keys и Secret.

3. Output Secret

Secret создаётся в namespace SentryProject, имеет type Opaque, ownerReference на exact CR
UID и содержит ровно один data key SENTRY_DSN. Имя по умолчанию <project-name>-sentry.
Foreign Secret никогда не перезаписывается. Удалённый owned Secret восстанавливается.

Secret cache manager ограничен двумя точными namespace: credential namespace оператора и
отдельный protected-state namespace. Для cross-namespace output Secret main создаёт
отдельный uncached Kubernetes client; credential/protected-state reads не расширены.
Reconcile остаётся периодическим, поэтому ручное удаление восстанавливается не позже
следующего reconcile, а не по глобальному Secret watch.

При rename:

1) создаётся new, old остаётся рабочим;
2) DSNReady=False/DSNCutoverPending;
3) требуется annotation sentryconfiguration.io/confirm-dsn-cutover=<new-name>;
4) после повторной authorization old удаляется, new становится current.

Автоматического timeout удаления нет. Protected binding хранит current/pending names, но
не DSN.

4. Revoke и временные ошибки

Однозначный текущий AccessDenied либо полный успешный key list с missing/inactive pinned
key удаляет только current/pending owned Secrets из protected binding. Перед каждым delete
policy и binding перечитываются. Unrelated и foreign Secrets не затрагиваются.

При timeout/403/transport error Sentry, ошибке чтения policy/Kubernetes или неоднозначном
состоянии рабочий Secret сохраняется. Paused также не запускает revoke. После policy
revoke status очищает dsnSecret и выставляет DSNAccessRevoked; после key revoke —
DSNKeyRevoked.

5. Workload contract

config/samples/workload_with_sentry_dsn.yaml использует обязательный secretKeyRef
optional=false. Kubernetes acceptance в kind доказывает CreateContainerConfigError до
Secret и Ready после его появления. Временное тестовое значение синтетическое.
